# venc for VS Code

[English](README.md) | [日本語](README.ja.md)

初めて使う場合は、画面操作を順番に説明した [USAGE.md](../USAGE.md) を参照してください。

二つのパスワードを使う暗号化 Vault を、保護された UTF-8 エディタと `venc://<vault-id>/` の仮想ワークスペースで編集します。
Rust が認証、保存時の暗号化、未保存の下書きの暗号化を担当します。二つとも必要ですが、二要素認証ではありません。

**既定は保護モードです。** 文書の内容を標準テキストモデルへ渡さず、仮想 FS の平文読み出しを拒否します。カスタムエディタのバックアップは Vault 内に暗号化して保存し、Save As は拒否します。
標準エディタによる平文バックアップの経路を防ぎます。侵害されたホストからのメモリ隔離や、swap・ダンプ・クリップボード・過去のバックアップの消去は保証しません。

## 導入と編集

1. VS Code デスクトップ版 1.95 以上で「Extensions: Install from VSIX...」からホストに対応する VSIX をインストールします。
2. アクティビティバーの **venc の金庫アイコン**をクリックして専用サイドバーを開きます。初期画面の **Create Vault** / **Open Vault** または上部のボタンから Vault を選びます。
3. 二つのパスワードを入力すると、`venc: Vault名` のワークスペースフォルダが追加されます。
4. Explorer でフォルダと空ファイルを作り、venc サイドバーの **Protected Files** から開きます。Vault ファイルの右クリック → **venc: Open in Protected Editor** でも開けます。
5. UTF-8 テキストを編集し、Ctrl/Cmd+S で保存します。上限はファイルごとに 16 MiB。不正な UTF-8 とバイナリは、内容を変更せず拒否します。

保護モードでは、通常のダブルクリックやテキストを読む拡張から Vault の内容を取得できません。専用ビューか右クリックを使ってください。
専用エディタは検索・置換（Ctrl/Cmd+F・H）、VS Code の Undo/Redo、Tab 入力、LF/CRLF 選択に対応します。履歴の平文は 32 MiB を上限に管理し、閉じる際に参照を解放します。言語サーバー、ノートブック、構文色分け、Vault 全体の検索、インポート、平文出力は提供しません。
BOM と既存の LF/CRLF を編集後も維持します。改行コードを明示的に変える場合はエディタ上部の選択欄を使います。
文書または親フォルダの名前変更・削除は、保護エディタを保存して閉じてから行ってください。

最初のフォルダ追加時に拡張ホストが再起動する場合があります。再度 `Open Vault` で認証してください。パスワードと鍵は自動復元しません。
復元エディタがロックエラーになったら、先に Vault を解除してから開き直してください。バックアップ ID は同じ Vault・文書パスでのみ復元できます。
古い下書きが新しい保存済み文書を上書きすることは拒否します。Revert する前に必要な下書きをメモリ上で確保してください。

## アクティビティバーとサイドバー

金庫アイコンを押すと専用の **venc** サイドバーを開きます。**Protected Files** に、記憶した Vault と現在の Vault ワークスペースフォルダを Locked / Unlocked の状態付きで表示します。
ロック中の Vault をクリックすると二つのパスワードを求めます。解除中の Vault は展開してフォルダをたどり、ファイルを保護エディタで開けます。
ロック中はファイルツリーを表示せず、復号したディレクトリ情報の取得も行いません。

上部には新規 Vault、別の Vault を開く、すべてロック、更新のボタンがあります。各 Vault の行にもロック・解除の操作を用意します。
ファイル・フォルダの作成、名前変更、削除は venc サイドバーのツールバー・右クリックから行えます。パス変更前に対象の文書を確認付きで保存して閉じます。ステータスバーの数はサイドバーと同じ Vault を対象にします。

## コマンドとロック

| コマンド | 動作 |
| --- | --- |
| Create Vault | 新規作成。既存ディレクトリは拒否 |
| Open Vault / Open Another Vault | 既存・復元 Vault の認証、または別の Vault の選択 |
| Open in Protected Editor | 標準 TextDocument を作らずに Vault テキストを開く |
| Lock Vault / Lock All Vaults | 保存して閉じ、アクセスを無効化して Rust の鍵を解放 |
| Change Vault Passwords | 現在の二つを再認証し、新しい二つを確認入力 |
| Forget Vault Location | ロックしてから、記憶した実ディレクトリの場所を削除 |

ステータスバーに解除中・ロック中の数を表示します。ロックのキャンセル、保存失敗、閉じる操作のキャンセルでは開いた状態を維持します。
保存時は暗号化オブジェクトの版を照合し、競合や保存中の追加編集があれば未保存状態を維持します。

フォルダの除去、アクセスモードの変更、コアの切断でアクセスを無効化し、保護パネルを閉じて内容への参照を解放します。
**予期しない切断では、最後の暗号化バックアップ以降の変更を失う可能性があります。** 暗号化された孤立下書きが残る場合があり、Recover Encrypted Drafts から一覧・別ファイル復旧できます。Vault Storage and Cleanup から容量を確認し、24時間以上前の参照されない文書オブジェクトを回収できます。下書きは自動削除しません。
通常のロックでは先に保存します。ロックは JavaScript・レンダラー・OS メモリの完全消去ではありません。

パスワード変更は同じマスター鍵のラッピングを更新します。古いスナップショットは古いパスワードで開けます。文書と暗号化下書きは再暗号化しません。
片方でもパスワードを失うと復旧できません。独立した暗号化バックアップを維持してください。

## 設定と互換モード

`venc.corePath` はマシン設定です。空なら同梱の `bin/venc`（Windows は `bin/venc.exe`）を使います。
独自コアはワークスペース側ホストの信頼できる実行ファイルを絶対パスで指定します。パスワード入力前にプロトコルと保護エディタ機能を確認します。
SSH / WSL / コンテナでは、そのホストの場所と実行ファイルを使用します。ブラウザ版 VS Code は未対応で、Workspace Trust が必要です。

`venc.allowPlaintextAccess` の既定値は `false` です。有効化すると標準 FileSystemProvider から平文を返し、通常エディタや他拡張が読み出せます。
**互換モードでは、Hot Exit 無効でも平文バックアップを作り得ます。** VS Code 1.95.3 で再現しています。
互換モードの開始には、このリスクの確認と `files.hotExit: "off"`、`workbench.localHistory.enabled: false` が必要です。
設定変更への同意は同じユーザープロファイルの他ファイルにも影響し、自動では元に戻しません。ワークスペースの上書きも一致する必要があります。
保護モードではこれらの全体設定を変更しません。モード変更はすべての Vault をロックするため先に保存してください。履歴設定を安全でない値へ変更すると互換セッションを切断します。

Vault ID、実パス、文書のパス・URI、内容を含まないバックアップ参照は、VS Code のプロファイルに残り得ます。
ファイル名の秘匿は Vault のメタデータについての保証であり、エディタの最近開いたファイルやワークスペースの記録には及びません。
既存の平文バックアップ・出力ファイルは削除しません。0.2.x から更新しても過去の通常エディタによるコピーは消えません。
暗号化されているという理由で Vault 内の設定やコードを信頼・実行しないでください。[セキュリティモデル](../SECURITY.md)も確認してください。

## 開発・検証・配布

Rust、C リンカー、Node.js 22.12 以上、npm が必要です。リポジトリのルートで:

```sh
cargo build --locked
cd vscode-extension
npm ci --ignore-scripts
npm test
npm run test:integration
npm run test:backups
npm run package
```

実際の Rust 子プロセスを使います。通常プロファイルの検証では、VS Code 自身がカスタム文書のバックアップを呼ぶまで待ち、暗号化下書きを復号照合し、Vault とプロファイルに文書の平文が残らないか調べます。比較対象として通常エディタの平文バックアップも再現します。
開発用プロファイルだけではバックアップの挙動を確認できません。Linux はディスプレイ / Xvfb と Electron ライブラリが必要です。`VENC_TEST_CORE` で別のコアを指定できます。

配布スクリプトは現在のホスト向けのコアをビルドし、`bin/` へ配置して、コンパイル済みコード・両言語の README・セキュリティモデルをまとめます。
他の OS・CPU は対応するホストで作成し、実行時のライブラリも確認してください。
Linux 静的ビルドは静的ライブラリと `RUSTFLAGS="-C target-feature=+crt-static"` が必要です。ローカル検証は Linux x64 で、他環境と独立したセキュリティ監査は未完了です。

参考: [Tree View とアクティビティバー](https://code.visualstudio.com/api/extension-guides/tree-view)、[VS Code カスタムエディタ](https://code.visualstudio.com/api/extension-guides/custom-editors)、[CustomEditorProvider API](https://code.visualstudio.com/api/references/vscode-api#CustomEditorProvider)。

**venc: Choose Editor Mode** から保護・標準編集を選べます。切り替え前に Vault を保存・ロックし、標準編集では平文アクセスとバックアップの条件を確認します。

**venc: Import Files** または同じホストのファイルをフォルダへドラッグして暗号化保存できます。原本を残し、既存ファイルは上書きしません。取り込みは1回100ファイル・各16 MiBまでで、キャンセルと結果表示に対応します。
