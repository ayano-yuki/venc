# venc for VS Code

[English](README.md) | [日本語](README.ja.md)

二つのパスワードを使う暗号化 Vault を、`venc://<vault-id>/` の仮想ワークスペースで編集します。
Rust 子プロセスが認証・保存時の暗号化を担当します。拡張自身は復号した一時ファイルを作りません。

**標準エディタは平文のクラッシュ用バックアップを作る場合があります。** Hot Exit を無効にしてもバックアップ生成は止まりません。これは検証済みの制約であり、「ディスクに平文が残らない」保証ではありません。

## 導入と Vault の開き方

1. VS Code デスクトップ版 1.95 以上で「Extensions: Install from VSIX...」からインストールします。
2. 独自のコアを使う場合、`venc.corePath` に拡張ホスト上の実行ファイルの絶対パスを指定します。信頼できる実行ファイルだけを使用します。
3. `venc: Create Vault` で親ディレクトリと新規名を選ぶか、`venc: Open Vault` で既存 Vault を選びます。
4. バックアップの制約を確認します。必要なら Hot Exit と Local History をユーザー設定で無効にする操作を明示的に承認します。
5. 二つのパスワードを入力すると、Explorer に `venc: Vault名` が追加されます。
6. 通常の操作でフォルダ・ファイルを作成、編集、保存できます。ファイルは最大 16 MiB です。

実行ファイルとプロトコルの設定エラーはパスワード入力前に確認します。パスワード入力のキャンセルでは認証後の変更を行いません。
最初のフォルダ追加時に拡張ホストが再起動する場合があります。
再起動後はロック通知の **Unlock** または `Open Vault` で再認証してください。パスワードは自動復元しません。

## コマンドと状態

| コマンド | 動作 |
| --- | --- |
| Create Vault | 新しい暗号化ディレクトリを作成。既存ディレクトリは拒否 |
| Open Vault | 復元された Vault フォルダを解除、または既存 Vault を選択 |
| Open Another Vault | ロック中のフォルダがあっても別の Vault を選択 |
| Lock Vault | 開いている Vault を選び、保存・エディタを閉じてから鍵を解放 |
| Lock All Vaults | 順にロック。保存失敗・キャンセルで停止 |
| Change Vault Passwords | 現在の二つを再認証し、新しい二つを確認入力 |
| Forget Vault Location | 開いていればロックし、記憶した実ディレクトリの場所を削除 |

ステータスバーに開いている数とロック中の数を表示します。クリックするとロックまたは解除操作を開きます。
複数の Vault はディレクトリ名と実パスで識別します。実ディレクトリの場所自体は秘密情報として扱いません。
復元されたフォルダは期待する Vault ID と照合し、同じパスに別の Vault が置かれていた場合は拒否します。

ロックをキャンセル、保存に失敗、タブを閉じる操作をキャンセルした場合は開いた状態を維持します。
非表示の未保存ノートブックも保存対象に含みます。
ロック時は仮想 FS を先に無効化し、その後にコアの鍵を解放します。無効化後、進行中の読み込み結果を返しません。
拡張ホストの再起動を避けるため、ロック後もワークスペース URI を残します。

パスワード変更はファイルを再暗号化しません。**過去のスナップショットは古いパスワードで解除できます。**
復旧キーはありません。独立した強いパスワードと、独立した暗号化バックアップを使用してください。

Vault のワークスペースフォルダを取り除くとセッションを切断します。
コア停止、タイムアウト、不正な応答、安全でない履歴設定への変更でもアクセスを無効化します。
予期しない切断を通知し、エディタバッファは再認証後に保存できるよう残る場合があります。
緊急切断で未保存内容を破棄したり、すべての平文を消去したと主張したりはしません。

## 設定と信頼

`venc.corePath` はマシン設定です。空なら同梱の `bin/venc`（Windows は `bin/venc.exe`）を使います。
信頼されたワークスペースで動作し、コアはワークスペース側で実行します。
SSH / WSL / コンテナでは、そのホストの実行ファイルと Vault の場所を指定してください。
ブラウザ版 VS Code は未対応です。コアはホストの OS・CPU・実行環境に対応している必要があります。
コアは初期ハンドシェイクに対応している必要があります。互換性のない実行ファイルはパスワード入力前に拒否します。パスワード変更機能を宣言していないコアでは、その操作を拒否します。

開く画面で `files.hotExit: "off"` と `workbench.localHistory.enabled: false` を確認します。
設定変更を承認すると**同じユーザープロファイルの他のファイルにも影響**し、自動では元に戻しません。
ワークスペースの上書き設定もこの条件に一致する必要があります。後から安全でない値に変更した場合は切断します。
拡張状態には Vault ID と実ディレクトリのパスだけを記憶します。
`Forget Vault Location` はこの対応を削除し、ワークスペース URI と暗号化された Vault 自体は残します。

## 平文が保存される経路

通常起動の VS Code 1.95.3 で、Hot Exit 無効でも未保存の仮想文書の平文バックアップが作られることを確認しています。
上記の設定は保存経路を減らすもので、すべてのバックアップを防止したり、古いコピーを削除したりするものではありません。

厳密な平文非保存には、VS Code のユーザーデータ・ワークスペース状態・バックアップ先を含めて、
適切なメモリ上のストレージを使う隔離環境を別途設定・検証する必要があります。
venc はその環境を作成・検証しません。RAM ストレージだけでは swap、休止状態、クラッシュダンプ、他プロセスの問題は解決しません。
暗号化バックアップを管理するカスタムエディタは今後の別設計であり、未実装です。

他の拡張、言語サーバー、検索、クリップボード、Save As、OS の機能にも平文が渡り得ます。
ロックは認識できる標準 Vault タブを閉じ、Rust の鍵を解放します。
VS Code のメモリ、他拡張のコピー、既存バックアップの完全消去は保証しません。
信頼できない Vault 内の設定を信頼済みワークスペースへ加えたり、暗号化されているから実行しても安全だと判断したりしないでください。
残る課題は [SECURITY.md](../SECURITY.md) に記載しています。

## 開発・検証・配布

Rust、C リンカー、Node.js 22.12 以上、npm が必要です。リポジトリのルートで:

```sh
cargo build --locked
cd vscode-extension
npm ci --ignore-scripts
npm test
npm run test:integration
npm run test:backups
```

プロバイダのテストは実際の Rust 子プロセスを使い、FS の契約、認証、パスワード変更、ロックのキャンセル、未保存ノートブック、待ち行列の上限、不正応答、ロックとの競合を検証します。
`test:integration` は VS Code 1.95.3 の隔離された開発用プロファイルで実際の文書編集・保存を検証します。
`test:backups` は通常起動の使い捨てプロファイルでディスクへのバックアップを検証します。開発用プロファイルではバックアップ先が省略される場合があるため分けています。
Linux ではディスプレイまたは Xvfb と Electron のライブラリが必要です。別のコアを使う場合は `VENC_TEST_CORE` を指定します。

このディレクトリを VS Code で開き、`venc.corePath` を設定して F5 で開発用拡張ホストを起動できます。
配布用パッケージは次で作成します。

```sh
npm run package
```

スクリプトが現在のホスト向けにコアをビルドし、新しい実行ファイルを `bin/` へ配置して、コンパイル済み拡張と両言語の README をパッケージします。
異なる OS・CPU の `--target` は拒否します。対応するホストでビルドし、動的ライブラリや Nix の実行環境の要件も確認してください。
Linux で静的ライブラリが利用できる場合は `RUSTFLAGS="-C target-feature=+crt-static" npm run package` で静的コアを作成できます。
今回の Linux x64 VSIX はローカルで検証済みです。macOS・Windows のパッケージはローカルでは未検証です。

参考: [FileSystemProvider API](https://code.visualstudio.com/api/references/vscode-api#FileSystemProvider)、[VS Code バックアップ実装](https://github.com/microsoft/vscode/blob/1.95.3/src/vs/workbench/services/workingCopy/common/workingCopyBackupTracker.ts)。
