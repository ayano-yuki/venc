# venc — Vault ENCrypt

二つのパスワードを必要とする暗号化 Vault の Rust プロトタイプです。
Rust コア、CLI、VS Code 拡張と仮想 FileSystemProvider を実装しています。
VS Code での導入・編集・ロック方法は [拡張の README](vscode-extension/README.md) を参照してください。
標準エディタのクラッシュ用バックアップに関する制約があります（下記参照）。

## ビルドと使用

Rust ツールチェーンと C リンカー（Linux では GCC または Clang）が必要です。

```sh
cargo build --release --locked
cargo test --workspace --locked
./target/release/venc init ./my-vault
./target/release/venc unlock ./my-vault
```

`init` は存在しないディレクトリに Vault を作成し、二つのパスワードを確認入力します。
`unlock` は端末でパスワードを入力し、鍵をメモリ内に保持するセッションを開始します。
パスワードを引数・環境変数・設定ファイルに保存する機能はありません。
セッション内では次の JSON 配列を一行ずつ入力します。スペースを含むパスも使えます。

```json
["add", "./document.txt", "notes/document.txt"]
["list"]
["extract", "notes/document.txt", "./exported.txt"]
["passwd"]
["remove", "notes/document.txt"]
["lock"]
```

- `add`: ローカルファイルを読み込み暗号化します。同じ Vault パスは更新します。
- `extract`: 認証・復号が成功した後、指定先へ**平文を書き出します**。既存パスは上書きしません。
- `passwd`: 現在の二つのパスワードを再認証して、新しい二つでマスターキーを再ラッピングします。
- `lock` / EOF / プロセス終了: セッションを終了します。プロセス間で鍵を永続化しないため、
  `add` / `extract` / `lock` は unlock セッション内のコマンドです。

CLI は暗号処理を検証するための開発用インターフェースです。VS Code 統合は専用の
`venc serve` 子プロセスへ匿名パイプで接続し、復号バッファを仮想 FS へ渡します。CLI の平文エクスポートは使いません。
仮想 FS は空ディレクトリ・ファイル作成・読み書き・名前変更・再帰削除を提供します。
フォルダの再帰インポートとチャンク暗号化は未対応です。

## 実装

| crate | 役割 |
| --- | --- |
| `venc-crypto` | Argon2id、HKDF-SHA256、XChaCha20-Poly1305、鍵バッファ |
| `venc-vault` | Vault 作成、セッション、暗号化メタデータ、ファイル操作、パスワード変更 |
| `venc-cli` | 非表示パスワード入力、対話セッション、拡張用 IPC サーバー |
| `vscode-extension` | TypeScript 拡張、Vault 開閉、仮想 FileSystemProvider |

Argon2id v19 を独立した 16-byte salt で順次二回実行します。
初期フォーマットでは 64 MiB / 3 iterations / parallelism 1 / 32-byte 出力に固定し、
読み込み時も一致を要求します（改ざんされた KDF コストによる過大なメモリ確保を防ぎます）。
Key A || Key B に HKDF-SHA256 を適用し、ランダムな 256-bit VMK をラッピングします。
VMK からメタデータ鍵と FEK ラッピング鍵を別々の用途文字列で導出します。
各書き込みは新しいランダムな FEK・オブジェクト ID・24-byte nonce を使います。
AAD はバージョン、用途、Vault ID、対象オブジェクト ID を結び付けます。

```text
my-vault/
├── vault.json       # 公開ヘッダと暗号化 VMK
├── metadata.enc     # 暗号化パス・サイズ・FEK ラッピング情報
├── .session.lock    # OS の排他ロック
└── objects/
    └── <random-id>.enc
```

v1 は JSON に byte 配列を保存します（添付例の base64 とは異なります）。
ファイルは最大 16 MiB、復号済みメタデータも最大 16 MiB です。
メタデータには空ディレクトリと更新時刻も含みます。新コードは旧プロトタイプのメタデータも読み込めますが、
更新後のメタデータは旧バイナリで読めません。フォーマットはまだ安定版ではありません。
ライブラリ API が返す鍵・復号バッファは `Zeroizing` で消去します。
ロックで VMK・メタデータのパス文字列を消去します。ただし呼び出し元が保持する復号バッファの
消去はその所有者の責任です。

### 保存と障害時の挙動

更新では新しいオブジェクトを作成・同期し、暗号化メタデータを同じディレクトリの一時ファイルから
置換します。パスワード変更も公開ヘッダのみを置換します。
Unix ではディレクトリも同期し、ファイル 0600 / ディレクトリ 0700 を指定します。
他 OS ではディレクトリ同期と Unix 権限の保証はありません。対象 OS・ファイルシステムでの
電源断テストは未実施で、すべての環境での耐障害性を保証するものではありません。
コミット失敗時は、置換済みかどうか不明な状態で追加更新しないようセッションをロックします。

既存オブジェクトは置換・削除時にも残します。途中の失敗で現在参照中のデータを失うことを避けるためです。
不要オブジェクトの回収は未実装で、更新・削除後も容量を使用します。
初期化が途中で失敗した場合、新規ディレクトリが残ることがあります。成功通知前の Vault は
未完成として扱ってください。自動的にそのディレクトリへ再初期化はしません。

OS の排他ロックで協調する venc プロセスの同時利用を拒否します。
シンボリックリンクのオブジェクトディレクトリ・ファイルは拒否しますが、悪意のあるローカルプロセスが
同時にパスを書き換える攻撃への完全な保護はありません。Vault の親ディレクトリを含め、信頼できる場所を使います。

## セキュリティ上の範囲

VS Code の標準エディタは Hot Exit を無効にしても、未保存の平文をクラッシュ用バックアップへ保存します。
VS Code 1.95.3 で実機確認済みです。仮想 FS の保存は暗号化されますが、通常のディスク全体へ平文を
残さない保証にはなりません。詳細と隔離環境の必要性は [拡張の README](vscode-extension/README.md#平文の保存に関する制約) を参照してください。

これは未監査のプロトタイプです。重要データへの利用前に、独立したレビュー・ファジング・
障害注入・プラットフォーム検証が必要です。
二つの秘密を要求する暗号化であり、二要素認証ではありません。
二つのパスワードのうち一方を失うと復旧できません。復旧キーは実装していません。
古い Vault 全体の復元（ロールバック）を検出する外部状態もありません。
パスワード変更後も、旧ヘッダのバックアップと旧パスワードを持つ人は同じ VMK を復元できます。
これは過去のバックアップからのアクセスを失効させる仕組みではありません。

暗号化オブジェクト数・サイズ・時刻は隠しません。OS の swap、クラッシュダンプ、端末出力、
Rust/OS 内部で作成されるすべての一時コピーの消去は保証できません。
VMK を使うプログラムを VS Code に限定する暗号学的保証もありません。

テストは二つのパスワードの必要性、用途とオブジェクトへの認証結合、改ざん・切り詰め、
ロック、排他セッション、パス検証、更新・削除、メタデータ認証、パスワード変更での
ファイル再暗号化の不要性を検証します。

暗号 API の参照: [RustCrypto Argon2](https://docs.rs/argon2/0.5.3/argon2/)、
[RustCrypto XChaCha20-Poly1305](https://docs.rs/chacha20poly1305/0.10.1/chacha20poly1305/)。
